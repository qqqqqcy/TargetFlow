# 页面布局规则与视觉验收

布局常量统一放在 `Dayflow/Dayflow/Utilities/DayflowLayout.swift`，尺寸单位为 macOS 逻辑点。

| 层级 | 规则 |
| --- | --- |
| 页面 | 左右 24、顶部 30、底部 24，仅由页面本身设置一次 |
| 页面标题 | 25 点粗体，副标题 12 点，标题与副标题间距 6 |
| 页面区块 | 纵向间距 16 |
| 时间线分栏 | 横向间距 12 |
| 设置一级卡片 | 内边距 20、圆角 12、边框 1 |
| 设置内容宽度 | 标题、tab 导航、记录／隐私／提供商一级卡片共用页面可用宽度 |
| 主次操作按钮 | 高度 34、圆角 8、左右内边距 14，13 点半粗字体；宽度随文字，不额外拉伸 |
| 时间线控件 | 录制、目标入口、复制、筛选、日／周与日历均沿用 34 点高度、8 点圆角 |
| 图标按钮 | 默认 34 × 34、圆角 8，图标保持原尺寸；摘要编辑、关闭、日期导航共用规则 |
| 特殊控件 | 日历日期网格、颜色选择点和播放进度控制按其交互语义保留专用布局，非普通操作按钮 |
| 多操作区域 | 间距 8，使用实际测量的自动换行布局，避免窄屏撑开卡片 |
| 多项长名称选择 | 使用菜单，避免模型名称横排挤压内容 |

页面容器外不要重复添加 padding。子 tab 不自行限制一级卡片最大宽度；文本编辑器、操作按钮等局部控件可按用途限制宽度。时间线保留日历、时间轴和详情三栏，各栏承担不同用途，不要求同宽；三栏整体与页面标题、目标条共用左右边界。

这次从实际 SwiftUI 窗口中确认了两个主要问题：设置页叠加外层 20 与内部 24 点边距；记录和提供商限制为 920 点宽，而 tab 导航、隐私页使用全部宽度。已删除重复边距和局部 920 点限制，统一标题与卡片布局。

视觉验收使用独立预览应用：

- 1320 × 800：检查时间线、记录与提醒、隐私、提供商实际截图，确认页面标题起点一致，设置 tab 导航与一级卡片左右边界一致。
- 940 × 680：检查记录、隐私和提供商，确认 tab、配置行、按钮完整显示，隐私应用网格自适应，屏蔽区可见。
- 900 × 640：补查时间线日／周切换、筛选和复制按钮，以及事件与目标弹窗的关闭、添加、调整颜色与完成按钮；底部操作保持完整可见。
- 按钮规则同时落在共享组件、时间线、摘要编辑、事件列表编辑／删除、分类选择浮层、回顾及设置操作上。侧栏导航、内联文字链接、系统菜单、日历日期、颜色点和播放控件保留对应语义的布局；未启用的历史页面未逐屏验收。
- 截图保存在被 git 忽略的 `build/layout-verification/`。

这是布局与视觉检查，不包含提供商连接测试或录屏验证。
